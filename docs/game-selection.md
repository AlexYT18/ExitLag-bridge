# Выбор игры из запущенных процессов

Этот интерфейс доступен в ветке `arch-linux-hardening` форка
`AlexYT18/ExitLag-bridge`. Старый upstream installer `v0.4.0-alpha.2` не
получает эти изменения после `git pull`: установленную программу нужно
обновить отдельно. Текущая цель проверки — Arch Linux x86_64.

## Обычный сценарий

1. Запустите игру обычным способом, например через Steam/Proton, и откройте
   сетевую сессию. У игры должны появиться сетевые сокеты.
2. В ExitLag Bridge откройте **Configure games...**, затем **Add running game...**.
   Настройка выполняется до запуска маршрутизации; при активном helper
   завершите текущую сессию Bridge.
3. Найдите игру по имени, PID или Steam AppID. **Refresh** обновляет список.
   По умолчанию служебные процессы скрыты; **Show all network processes**
   показывает остальные доступные сетевые процессы вашего пользователя.
4. Выберите строку. Для Wine/Proton программа подставляет фактические prefix и
   loader сама. **Windows game image** показывает проверенные `.exe`,
   отображённые в память выбранного процесса. Единственный вариант выбирается
   автоматически; при нескольких вариантах выберите нужный.
5. Если image не найден, **Choose game .exe...** позволяет выбрать настоящий
   файл игры. Windows-путь получается через реальные drive mappings этого
   prefix; выдуманный путь вида `C:\Games\...` не создаётся.
6. Нажмите **Add selected game**, затем **Save**. Перед добавлением повторно
   проверяются процесс, сокет и выбранный image. Если игра перезапустилась или
   сменила сокеты, обновите список и выберите её заново.
7. Запустите ExitLag, выберите ту же игру в официальном клиенте и примените
   маршрут. Переподключите игру, чтобы появились новые соединения.

Обычному Proton/Wine сценарию больше не нужны ручной ввод Linux-путей к prefix
и loader или редактирование Tab-separated строк. Если ОС не позволяет получить
надёжные данные процесса, программа сообщает об этом вместо предположений.

## Что означают данные списка

Имя процесса и Steam AppID помогают найти игру. Основание привязки — UID,
generation процесса, executable из `/proc`, inode сокета и реально удерживаемый
fd. Аргументы командной строки не используются как доказательство executable.

Найденный PE-файл и его Windows-путь не подтверждают, что официальный клиент
распознал игру или запросил redirect. Это проверяется следующим этапом.
Показанные TCP/UDP сокеты также не подтверждают направление игрового трафика.
По умолчанию desktop launcher использует **TCP**. Новый переключатель
**Experimental UDP** явно включает экспериментальный режим синхронных UDP
callbacks; его IPv4/IPv6 проверки используют локальные синтетические серверы.
Поддержка конкретной игры и трафик через сервис ExitLag требуют отдельного
подтверждения. Ограничения: [UDP](udp-multi.md).

Для native Linux игры соответствующая Windows identity может быть неизвестна.
**Advanced identity...** оставляет возможность явно указать подтверждённое
пользователем значение. Закрытый каталог ExitLag не заменяется догадками.

## Существующие настройки

Основное окно показывает настроенные игры и позволяет удалять строки.
**Advanced...** сохраняет прежний текстовый редактор, file pickers и комментарии.
Старые двухколоночные prefix rows помечаются **Needs review**. Их можно удалить
из списка и заново добавить через работающий процесс. Они не мигрируют с
угаданным loader и не выбрасываются без действия пользователя.

Настройки сохраняются приватно и атомарно. Изменения в другом окне не
перезаписываются молча. Права, формат и существование источников проверяет
тот же parser, который использует установленный supervisor.

Привязка Wine/Proton разрешает выбранный runtime во всём prefix. Она не
удостоверяет конкретный Windows image при каждом запуске; отдельные game
prefixes предпочтительнее общего prefix. Подробнее —
[границы process identity](process-identity-translation.md).

## Проверки разработки

```sh
python3 tests/test_process_picker.py
python3 tests/test_game_picker.py
python3 tests/test_linux_packaging.py
python3 tests/gui-picker-smoke.py
```

Последний тест запускает настоящий Tk в отдельном Xvfb с synthetic process
provider. При отсутствии Xvfb он возвращает SKIP 77. Для Arch нужен пакет
`xorg-server-xvfb` и установленный шрифт, например `ttf-dejavu`. Аккаунт,
коммерческий клиент и игра этим тестам не нужны.
Результаты и ограничения конкретной итерации —
[PROCESS_PICKER_ITERATION.md](audit/PROCESS_PICKER_ITERATION.md).
